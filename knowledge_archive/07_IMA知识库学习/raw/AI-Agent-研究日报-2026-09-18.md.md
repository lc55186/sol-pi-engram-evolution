### 🔴 发现 1：MemGraphRAG — 三层全局记忆驱动的 GraphRAG 新范式（KDD 2026）

**来源**: [arXiv:2606.00610](https://arxiv.org/html/2606.00610) | [GitHub](https://github.com/XMUDeepLIT/MemGraphRAG)

MemGraphRAG 提出了一个**基于记忆的多智能体系统**来解决传统 GraphRAG 的核心痛点：

- **三层全局记忆结构 (Three-Layer Global Memory)**：
  - Schema Layer（M_ont）：抽象本体模式及抽取频率
  - Fact Layer（M_fac）：具体实体-关系三元组
  - Passage Layer（M_pas）：原始文本段落作为证据锚定
  - 三层之间有双向索引：schema↔fact 对齐 + fact↔passage 证据锚定

- **多智能体协作组**：
  - Extraction Agent → 抽取 schema/fact/passage
  - Conflict Detection Agent → 检测冗余、结构异常、逻辑矛盾
  - Conflict Resolution Agent → 利用 schema 约束和历史证据解决冲突

- **核心创新**：将知识图谱构建从"逐文档块独立抽取"重新定义为"全局记忆 M 与知识图谱 G 的动态共演化过程"，通过全局仲裁保持主题相关性和逻辑一致性，通过记忆引导桥接解决结构碎片化。

> **对我们的启示**：这是 Graph Memory 从"静态索引"迈向"动态记忆共演化"的标志性工作。三层结构 + 多智能体协作的模式值得在 IMA 知识库场景中参考。

### 🟠 发现 2：Microsoft Agent Framework 正式发布 — AutoGen + Semantic Kernel 的继任者

**来源**: [Microsoft Learn](http://learn.microsoft.com/en-us/agent-framework/overview) | [arXiv:2606.20058](https://arxiv.org/pdf/2606.20058)

微软正式将 AutoGen 和 Semantic Kernel 合并为 **Microsoft Agent Framework**，定位为下一代多 Agent 编排基础设施：

- **核心能力**：
  - **Agent**：支持 Microsoft Foundry、Anthropic、Azure OpenAI、OpenAI、Ollama 等多模型
  - **Agent Harness**：内置长期任务支持 — 规划/todo tracking、上下文压缩、文件访问与记忆、工具审批机制、可观测性
  - **Workflows**：函数式 + 图式工作流，显式控制多 Agent 执行路径
  - **Integrations**：MCP clients、中间件、context providers、evaluation services

- **关键架构决策**：
  - Workflow vs Agent 选择标准："当过程有明确定义的步骤时用 Workflow，当任务开放/对话式时用 Agent"
  - 支持 C#、Python、Go（Go 预览版）
  - 显式多 Agent 执行路径控制，而非完全自主

- **生态信号**：
  - A2A Protocol (Agent-to-Agent) 已标准化：https://a2a-protocol.org
  - MCP-Bench、Tool Decathlon、MCPMark 等新基准表明：规划和协调（而非语言理解）是区分 Agent 性能的关键

> **对我们的启示**：微软将 Agent Framework 定位为企业级多 Agent 编排标准，结合 MCP/A2A 协议，正在构建类似"Agent 操作系统"的基础设施层。

### 🟡 发现 3：RK3588 NPU LLM 推理突破 — Gemma-4 E2B 达 9.1 tok/s

**来源**: [GitHub: Sinclear/rk3588-llama-npu](https://github.com/Sinclear/rk3588-llama-npu)

RK3588 NPU 的 llama.cpp 优化取得实质性进展：

| 模型 | 参数量 | 量化 | RSS | 解码速度 | 质量 |
|------|--------|------|-----|----------|------|
| Gemma-4 E2B | 4.6B dense | Q8_0 | 4.7 GB | **9.1 tok/s** | 5/5 |
| Qwen2.5-Coder-3B | 3B dense | Q8_0 | 3.0 GB | 8.1 tok/s | 4/5 |
| Qwen3.5-4B | 4B dense | Q8_0 | 4.3 GB | 5.9 tok/s | 5/5 |
| Gemma-4 E4B | 7.5B dense | Q8_0 | 7.6 GB | 5.0 tok/s | 5/5 |
| T-lite 8B | 8B dense | Q8_0 | 7.5 GB | 4.1 tok/s | 5/5 |

- **关键优化技术**：
  1. **Tiling Cache v5** — 预计算 segments/offsets，消除重复计算（168 matmul/token）
  2. **madvise Page Release** — NPU DMA 后释放重复 GGUF mmap 页面，RSS 13.5→7.5 GB
  3. **C-bound / B-bound Skip** — 跳过 `rknn_matmul_set_io_mem` 重复调用

- **NPU 解码时间分布**（T-lite 8B Q8_0, 168 matmul/token）：
  - NPU_run: 153-166ms (80%)
  - C_sync: 23-38ms (17%)
  - A_prep: 5-7ms (3%)

- **重要注意事项**：必须使用 `taskset 0xf0` + `-t 4` 锁定大核（A76），否则小核（A55）会拖慢 NPU 推理 17-33%。

> **对我们的启示**：RK3588 在 4-7B 级别模型上已具备实用推理能力（5-9 tok/s），结合量化可跑 8B 模型。NPU 瓶颈在 C_sync 和 DMA 同步，非计算本身。

### 🟢 发现 4：Token 优化进入"工具输出压缩"新战场 — sqz 与 LCLM

**来源**:
- [sqz whitepaper](https://github.com/ojuschugh1/sqz/blob/main/docs/whitepaper.md)
- [LCLM: Latent Context Language Models](https://dataworldbank.net/2026/06/11/context-compression-finally-works-in-production)
- [Token Reduction Is Not Cost Reduction](https://arxiv.org/pdf/2607.12161)

**两个并行突破**：

**A. sqz — 工具输出预注入压缩**
- 针对 Agent 会话中工具输出（shell 命令、文件读取、API 调用结果）积累导致上下文膨胀的问题
- 在内容**进入 LLM 上下文窗口之前**进行压缩，保持 prompt cache 有效性
- 技术组合：
  - 领域特定结构化格式化器
  - 内容寻址去重（SHA-256 内容缓存 → 13 token 引用标记 §ref:HASH§）
  - 自适应压力感知压缩
  - 熵基安全路由
- 实测：3,003 次生产压缩，节省 178,442 tokens，首次压缩平均减少 24.7%，重复读取最高节省 92%

**B. LCLM (Latent Context Language Models) — 编码器-解码器压缩**
- NYU/Columbia/Princeton/UMD/Harvard 联合提出
- 0.6B 编码器 + 4B 解码器架构
- 4x 压缩：RULER 准确率 91.76%（vs 无压缩 94.41%）
- 16x 压缩：准确率 75.06%（移除 93.75% 输入 tokens）
- 在 1M tokens 上下文时，标准 KV cache 在单张 H200 上内存溢出，LCLM 在 16x 压缩下仍可运行

**C. 反直觉发现："Token 减少 ≠ 成本降低"**
- arXiv:2607.12161 研究表明：最激进的压缩减少 38.4% 工具输出 tokens，但**增加 6.8% 计费成本**
- 原因：prompt-cache 流量占大部分输入成本，工具输出压缩可节省的比例有限
- 压缩可能改变 Agent 轨迹（引发额外检索/诊断/测试），抵消本地 token 节省

> **对我们的启示**：Token 优化正从"提示词压缩"扩展到"工具输出压缩"和"架构级压缩"。sqz 的去重机制对 IMA 知识库场景尤其相关。

### 🔵 发现 5：GraMRAG — 图记忆 + 强化学习驱动多 Agent 多步推理（arXiv 2026.09.12）

**来源**: [arXiv:2609.14066](https://arxiv.org/abs/2609.14066) | 2026年9月12日最新提交

GraMRAG 提出了一个**图记忆引导的多 Agent RAG 框架**，解决现有多 Agent RAG 系统的两个核心局限：

- **推理深度不足**：现有系统在多步跨模态推理中检索不充分
- **状态盲区 (State Blindness)**：Agent 在长时序任务中缺乏对全局推理状态的感知

**核心创新**：

1. **动态多模态记忆图 (Multimodal Memory Graph)**：
   - 将 Agent 推理形式化为有向无环图 (DAG)
   - 显式建模 action-observation 依赖关系
   - 抑制冗余检索，缓解状态盲区

2. **视觉-文本桥接推理**：
   - 多尺度实体裁剪 + ReAct 风格视觉工具链
   - 统一处理视觉和文本模态

3. **拓扑感知策略优化 (TAPO)**：
   - 利用图拓扑进行关键路径识别
   - 针对性节点剪枝
   - 跨多步推理轨迹的细粒度信用分配

> **对我们的启示**：将推理过程建模为 DAG + 图记忆，比传统的线性对话记忆更适合复杂多步任务。TAPO 的"关键路径识别 + 节点剪枝"思路可应用于 Agent 效率优化。
