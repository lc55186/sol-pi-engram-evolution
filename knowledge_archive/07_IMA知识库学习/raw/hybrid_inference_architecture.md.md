## 2. 路由策略

### L0: 本地极速路由（< 200ms）
- **触发条件**：简单问候、状态查询、本地缓存命中
- **执行位置**：纯本地（无网络依赖）
- **模型**：规则引擎 + 本地缓存
- **成本**：0

### L1: 端侧模型路由（200ms ~ 2s）
- **触发条件**：中等复杂度分析、隐私敏感场景、网络不稳定
- **执行位置**：RK182X/1860 NPU
- **模型**：Qwen3.8-27B INT4（复杂推理）/ MiniCPM5-2B（轻量实时）
- **成本**：0（本地推理无API费用）

### L2: 云端模型路由（2s ~ 5s）
- **触发条件**：复杂推理、长上下文分析、多模态理解、端侧超时
- **执行位置**：DeepSeek V4.1 Flash API
- **模型**：deepseek-flash（V4.1 Flash）
- **成本**：$0.15/M input + $0.60/M output

### 路由决策树

```
用户输入
  │
  ├── 简单规则匹配？ ──YES──▶ L0 本地响应
  │   (问候/状态/缓存)
  │
  ├── NO
  │   │
  │   ├── 隐私敏感数据？ ──YES──▶ L1 端侧推理
  │   │   (财务/合同/个人信息)
  │   │
  │   ├── NO
  │   │   │
  │   │   ├── 网络可用？ ──NO──▶ L1 端侧推理
  │   │   │
  │   │   ├── YES
  │   │   │   │
  │   │   │   ├── 端侧NPU负载<80%？ ──YES──▶ L1 端侧推理
  │   │   │   │   (中等复杂度任务)
  │   │   │   │
  │   │   │   ──NO──▶ L2 云端推理
  │   │   │       (复杂推理/长上下文/多模态)
```

## 3. 成本优化策略

### KV Cache 复用（V4.1 Flash核心优势）
- 多轮谈判场景：30轮对话的上下文缓存只需计算一次前缀
- 成本节省：相比无缓存，节省约 **70%** input tokens

### 闲时推理
- V4.1 Flash 闲时价格 = 高峰的50%
- 非紧急分析任务（谈判复盘、数据整理）可调度至闲时执行

### 端云负载均衡
- 网络良好 + NPU空闲 → 优先端侧
- 网络差 + NPU满载 → 云端接管
- 混合推理：端侧做初步分析，云端做深度决策

## 4. 数据流设计

### 实时谈判模式
```
麦克风 → VAD → ASR → 路由层 → L1/L2推理 → 提示生成 → TTS/震动
         │                            │
         └──── 本地缓冲 ◀──────────────┘
```

### 离线模式（无网络）
```
麦克风 → VAD → 端侧ASR → L1端侧推理 → 本地提示生成 → 震动/文字
```

### 同步策略
- 网络恢复后，本地缓存的谈判数据自动同步至云端
- Engram记忆增量同步（仅传输变更部分）
- 冲突解决：时间戳优先 + 用户确认

## 5. 安全与隐私

| 数据类型 | 端侧处理 | 云端传输 | 存储 |
|----------|---------|---------|------|
| 声纹特征 | ✅ AES-256 | ❌ 禁止 | session_only |
| 谈判内容 | ✅ 优先 | ⚠️ 加密+脱敏 | 90天过期 |
| 决策推理 | ✅ 优先 | ⚠️ 仅传输必要上下文 | 不存储 |
| 用户画像 | ✅ 本地 | ❌ 禁止 | 本地加密 |
