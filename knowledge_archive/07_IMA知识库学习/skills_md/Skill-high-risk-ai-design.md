# 高风险AI产品设计原则：代价不对称下的决策框架

> 核心洞察：同一个技术工具，当"输错的代价"从"多翻一页"变成"一条人命"时，每个决策都会被单向压向安全端。

## 〇、使用前强制检查（不可跳过）

新建或修改任何AI产品/功能时，**必须**先回答：

**"这里错了，代价谁承担、可不可逆？"**

| **答案**          | **分类**   | **设计方向**         |
| --------------- | -------- | ---------------- |
| 不可逆（生命/重大财产/法律） | **安全决策** | 单向兜底 + 规则锁死 + 留痕 |
| 可逆（体验/效率/偏好）    | **体验决策** | 平衡最优 + 加权分数      |

**混用是最大事故根源**：拿做体验的平衡心态，去做安全的事。

## 一、融合策略：取严原则

### 通用 RAG（共识模式）

```
规则路判 L3 + 语义路判 L1 → RRF 融合 → L2（折中）
```

灵魂：多方印证压误报，求共识。

### 高风险分诊（取严模式）

```
规则路判 L3 + 语义路判 L1 → 取严 → L1（高严即采纳）
```

灵魂：**漏判 > 误报**，宁可虚惊一场，不可漏掉一命。

### 判断规则

* 任一路喊最高级 → 直接采用，**绝不取折中**
* 误报是成本指标（设软上限，不卡上线）
* 漏判是红线指标（逼近 0）

> **记忆口诀**：召回怕漏也怕烦，要共识来平衡；分诊只怕漏、不怕烦，要兜底。

## 二、评测指标：零容忍标准

| **维度** | **通用做法**              | **高风险做法**             |
| ------ | --------------------- | --------------------- |
| 核心指标   | Precision + Recall 均衡 | **L1 漏判率 → 0**（敏感度）   |
| 误报定位   | 与漏判同等权重               | **降为成本指标**，设软上限       |
| 标准答案来源 | 直接用历史标签               | 历史标签不可靠时需专家重标         |
| 罕见危急   | 依赖真实数据覆盖              | **主动造对抗案例**（专家编写）     |
| 数据隔离   | 无强制要求                 | **训练集/评测集严格隔离**（防背答案） |

### 实操红线

```
L1 漏判率 = 被错判为 L2/L3 的真实 L1 案例数 / 全部真实 L1 案例数 → 目标：0
误报率   = 被错判为 L1 的真实 L3 案例数 / 全部真实 L3 案例数 → 软上限：别把值班淹没
```

## 三、兜底默认值：最安全端

**不确定 = 中间态 = 最大风险**

| **场景**   | **通用做法**  | **高风险做法**              |
| -------- | --------- | ---------------------- |
| 模型说"不知道" | "我帮您转人工"  | **先按 L1 处理 + 转人工并行**   |
| 双路全军覆没   | 等待/重试     | **默认 L1，立即弹 120 + 告警** |
| 信息不足     | "请补充更多信息" | **按最坏情况假设**            |

**原则**：安全决策的兜底值，必须落在最安全的那一端，而非"中间"或"观望"。

## 四、规则锁死 vs 加权分数

### 核心区分

```
不可逆决策 → 规则锁死（直接过滤出局，不参与打分）
可逆决策   → 加权分数（求最优平衡）
```

### 实例对照

| **决策**      | **错误代价**      | **正确做法**        | **错误做法**      |
| ----------- | ------------- | --------------- | ------------- |
| 医生推荐：明天是否出诊 | 会员选了约不上 → 体验崩 | **硬约束过滤**       | 扣20分，结果约不了    |
| 医生推荐：既往主诊医生 | 招牌"懂你、连续"碎掉   | **置顶规则，不参与打分**  | 加30分，被别的维度压过去 |
| 融合策略：两路打架   | 漏判 → 人命       | **取严：任一喊L1即L1** | RRF求共识 → L2   |
| 止损触发：股价暴跌   | 亏损扩大          | **任一触发即执行**     | 投票等共识         |

### 判断口诀

> **不能输的东西，交给规则，不交给分数。**

## 五、核验"感知不存在"

**场景**：会员半夜抱着发烧老人，最不能忍"正在核验您的身份..."

**设计目标**：核验在感知里"不存在"，300ms内完成，不中断服务流。

**工程实现**：

```
前台：0延迟接住 → 倾听症状 → 问所在地
后台：并行静默核验权益 → 只在异常时打断
```

**空窗期红线**：

* ✅ 验证前只用"对方主动告诉我的"
* ❌ 绝不主动暴露"从档案里读出来的"
* ✅ 第一句就是 L1 → 120 不等核验（安全核验给救命让路）

## 六、交接班：原话 + 溯源 + 显式担责

### 交接班三要素

| **要素**   | **说明**           | **反模式**       |
| -------- | ---------------- | ------------- |
| **原话保留** | AI研判是有损压缩，原话原封不动 | 只给AI摘要，吃掉关键信息 |
| **溯源标注** | AI命中的红旗条文塞进去     | 医生说不出"为什么判L1" |
| **显式担责** | 降级必须点按钮+填理由+留痕   | 医生"心里想想"默默降级  |

### 显式降级机制（核心安全装置）

```
医生要降级 L1→L2/L3：
  ① 必须在系统里点"降级"
  ② 必须填理由
  ③ 必须签名担责
  ④ 不走这个流程 → 工单对系统永远 = L1
  ⑤ 120催拨、SLA计时、未结案告警 全按L1跑
```

> **核心**：AI 不能降级，医生也不能"默默降级"，只能"正式降级"。

### JSON Schema 机器强制

```json
{
  "type": "object",
  "required": ["original_dialogue", "fusion_mode", "level"],
  "properties": {
    "original_dialogue": {"type": "string", "minLength": 1},
    "fusion_mode": {"const": "strictest"},
    "level": {"enum": ["L1", "L2", "L3"]},
    "downgrade": {
      "type": "object",
      "required": ["doctor_id", "reason", "signature"]
    }
  }
}
```

> 写进注释的纪律会被忽略，写进 Schema 的，绕不过去。

## 七、优先级栈（不可违反）

```
救命 > 体验 > 安全核验 > 个性化
 ↑高阶约束绝对优先于低阶，不可妥协
```

* 救命 vs 个性化 → 救命
* 救命 vs 核验 → 救命
* 体验 vs 个性化 → 体验
* 个性化可以交给分数博弈，救命/体验必须用规则锁死

## 八、适用范围（不只医疗）

任何存在**代价不对称**的场景：

| **领域** | **不可逆代价**       | **对称代价**      |
| ------ | --------------- | ------------- |
| 医疗分诊   | 漏判心梗 → 死亡       | 误报 → 虚惊一场     |
| 金融风控   | 漏过欺诈 → 资金损失     | 误拦正常交易 → 客诉   |
| 内容安全   | 漏过违法 → 法律风险     | 误删正常内容 → 用户不满 |
| 自动驾驶   | 漏判行人 → 车祸       | 误刹 → 后车追尾     |
| 政务AI   | 漏判紧急事件 → 公共安全事故 | 误报 → 多派一次车    |

## 九、决策速查表

```
新建/修改AI功能 → 问：错了代价谁承担、可不可逆？
  ├── 不可逆 → 安全决策
  │     ├── 融合取严：任一喊高严即采纳
  │     ├── 兜底默认最安全端
  │     ├── 评测死保漏判率→0
  │     ├── 硬约束直接过滤（不参与打分）
  │     ├── 降级必须显式+留痕
  │     └── 交接班原话+溯源
  │
  └── 可逆 → 体验决策
        ├── 加权求最优
        ├── RRF/投票求共识
        ├── Precision+Recall 均衡
        └── 个性化排序
```

## 十、与本仓库其他系统对照

| **现有系统**                | **本原则对应** | **可强化点**       |
| ----------------------- | --------- | -------------- |
| medical-diagnosis skill | 直接映射      | 补"显式降级"+"评测隔离" |
| stock-analyst 止损        | 安全决策→取严   | 止损不应投票，任一触发即执行 |
| privacy-guard 隐私泄露      | 安全决策      | 规则锁死，不加权       |
| Hermes Skill 设计         | 规则 vs 分数  | "不能输的东西，交给规则"  |
| 梦境系统                    | 体验决策      | 可加权平衡          |
