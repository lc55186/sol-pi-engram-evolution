# 专利技术交底书生成技能

从项目源码和文档自动生成符合 CNIPA 标准的专利交底书。

## 官方规范依据

本技能遵循国家知识产权局官方标准：

* 100001权利要求书模板 - 权利要求撰写规范
* 100002说明书模板 - 说明书五部分结构
* 100003说明书附图模板 - 附图绘制规范
* 100004说明书摘要模板 - 摘要300字限制
* 2025年专利申请文件撰写指导手册 - 撰写技巧详解
* 发明专利申请文件撰写与指导手册 - 审查答复要点
* **\[发明专利新申请办理规范与文件撰写模板]** - 完整格式规范，见 `references/cnipa-format-2025.md`

## 触发条件

当用户提到"专利交底书"、"技术交底"、"撰写交底书"、"专利撰写"、"patent disclosure"、"权利要求"、"专利查新"、"CNIPA检索"时激活。

## 核心能力

1. **智能分析**：扫描项目结构、README、技术文档，识别专利创新点
2. **查新检索**：通过 CNIPA（国家知识产权局）检索现有技术，获取专利号和摘要
3. **交底书生成**：生成符合 CNIPA 标准的6章结构交底书
4. **图表生成**：生成 Mermaid 架构图、流程图、时序图
5. **Word导出**：自动转换为 Word 文档
6. **批量生成**：支持多篇专利并行生成

## 文档提取注意事项

提取 .docx/.pdf 文档时的降级策略：

```
delegate_task (子任务并行提取)
    ↓ 超时或不完整
直接 terminal + python-docx/pdfplumber (单文件提取)
```

* delegate\_task 适合批量但可能慢/不完整
* 直接 python-docx 提取更可靠，适合 ≤10 个文件
* 提取后保存为 .txt 供后续分析

## 用户提供格式文档的处理流程（重要）

当用户提供新的格式规范文档（.docx/.pdf/.md）时：

1. **先提取文档内容** - 使用 python-docx 或 markitdown 提取文本
2. **对比现有规范** - 识别与当前 skill 规范的差异点
3. **更新 skill 文件** - 在生成交底书之前，先更新 `disclosure_builder.md` 和/或 `template_reference_official.md`
4. **再生成输出** - 使用更新后的规范生成交底书

**关键教训**：不要跳过步骤3直接生成，否则输出可能不符合用户最新要求。

## 8步工作流（完整版）

### Step 1: 需求采集（`intake.md`）

* 确认项目路径、产出目录、专利类型
* 明确技术领域和发明人信息

### Step 2: 项目扫描（`project_scanner.md`）

* 扫描项目结构，识别核心模块
* 提取技术关键词

### Step 3-4: 专利点挖掘（`patent_points_analyzer.md`）

* 生成候选专利点列表
* 每个专利点包含：创新点、现有技术对比、保护方向
* **质量评估**：检查是否有明确技术特征、可实施性、非显而易见性

### Step 5: 查新检索（`prior_art_search.md`）

* CNIPA检索 → Google Patents → 人工分析
* 输出 JSON：\{patent\_no, applicant, title, abstract, url}

### Step 6: 交底书预览（`disclosure_preview.md`）

* 生成6章结构预览，供用户确认

### Step 7: 交底书生成（`disclosure_builder.md` + `template_reference.md`）

* 生成完整交底书（含Mermaid图）
* 同时生成 Word 文档

### Step 8: 交付与迭代

* 交付交底书文件
* 提供权利要求偏向建议（方法/系统/装置）
* 支持迭代修改

## 官方格式规范（摘要300字限制）

根据100004说明书摘要模板，摘要必须：

* 不超过300字（含标点）
* 不得加标题
* 包含五要素：名称+技术领域+技术问题+技术方案要点+主要用途
* 指定摘要附图（最能说明技术特征的图）

**示例结构：**

```
本发明涉及[技术领域]，公开了一种[发明名称]，用于解决[技术问题]。
该方法包括：步骤1...，步骤2...，步骤3...。
主要用途是[应用场景]。
```

## 官方格式规范（说明书五部分）

根据100002说明书模板，说明书必须包含：

1. **技术领域** - 一句话说明所属技术领域（50-100字）
2. **背景技术** - 现有技术及其缺陷（300-800字）
3. **发明内容** - 要解决的技术问题+技术方案+有益效果（200-500字）
4. **附图说明** - 各附图的简要说明（每图20-50字）
5. **具体实施方式** - 详细实施例（1000-3000字）

## 官方格式规范（权利要求书）

根据100001权利要求书模板：

* 使用"权利要求书"标题
* 独立权利要求用序号1开始
* 从属权利要求引用格式："根据权利要求X所述的..."
* 使用"其特征在于"界定技术特征
* 保护范围从宽到窄逐级限定

## 官方格式规范（附图）

根据100003说明书附图模板：

* 尽量竖向绘制
* 两幅以上用"图1"、"图2"顺序编号
* 编号标注在图正下方
* 仅保留必要文字

## 输出格式（技术交底书 6 章结构）

> **⚠️ 格式区分**：技术交底书 ≠ 说明书 ≠ 专利申请文件。
>
> * **技术交底书**（Step 7 生成）：内部文档，给专利代理人看，格式灵活，6章结构。
> * **说明书**（代理人转换）：正式申请文件，格式严格，5部分结构（技术领域/背景技术/发明内容/附图说明/具体实施方式），段落编号 `0001.`\~`XXXX.`。
> * **专利申请文件**（完整包）：权利要求书 + 说明书 + 说明书摘要，用户可能要求直接生成此格式。
> * 交底书→申请文件的转换规则见下方「交底书转专利申请文件」一节。

### 交底书转专利申请文件

当用户要求"按正式专利申请格式重写"时，从6章交底书转换为3部分申请文件：

**输出结构**：

1. **权利要求书** — 从第5章"技术关键点和欲保护点"扩展
   * 独立权利要求：前序部分 + 「其特征在于」+ 特征部分
   * 从属权利要求：「根据权利要求X所述的…，其特征在于，…」
   * 编号 `1.` `2.` `3.`，每条结尾仅1个句号，至少8条
2. **说明书** — 从第1-4章+第6章重组
   * 段落编号 `0001.` `0002.` ... 连续编号
   * 结构：技术领域 → 背景技术 → 发明内容 → 附图说明 → 具体实施方式
   * **禁用 Mermaid**，用文字描述替代
3. **说明书摘要** — ≤300中文字符，全文不分段
   * 包含五要素：技术领域 + 技术问题 + 方案要点 + 有益效果

**转换要点**：

* 第1章"技术背景" → 说明书"背景技术"（段落编号从 `0002.` 起）
* 第2章"技术问题" + 第3章"技术方案" → 说明书"发明内容"
* 第3章"模块说明"/"流程说明" → 说明书"具体实施方式"（最长部分）
* 第4章"优点" → 说明书"发明内容"的有益效果部分
* 第5章"权利要求" → 独立/从属权利要求书（格式严格化）
* 所有 Mermaid 图 → 文字描述的"附图说明"

**批量并行**：≥2份文件时用 `delegate_task` 并行，每批≤3个子任务（平台并发限制）。批量重写工作流详见 `references/batch-rewrite-workflow.md`。

### 6章结构

1. **技术背景与现有技术**（1.1 现有技术 + 1.2 现有技术缺点）→ 对应说明书"背景技术"
2. **本发明所要解决的技术问题** → 对应说明书"发明内容"的问题部分
3. **技术方案详细阐述**（3.1 背景 + 3.2 系统框图 + 3.3 模块说明 + 3.4 流程说明 + 3.5 关键参数）→ 对应说明书"发明内容"方案部分 + "具体实施方式"
4. **与现有技术相比的优点** → 对应说明书"发明内容"效果部分
5. **技术关键点和欲保护点** → 对应"权利要求书"
6. **其它**（实施例、技术效果、参数示例）→ 对应"具体实施方式"补充

### 图表规范

* 使用 Mermaid 语法（`flowchart TB`、`graph LR`）
* 系统框图用 `subgraph` 分层
* 流程图用 `flowchart TD`
* 时序图用 `sequenceDiagram`
