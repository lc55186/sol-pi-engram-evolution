# 节点类型
## 任务节点 (TaskNode)
- task_id: str (唯一ID, UUID)
- title: str (任务标题)
- description: str (任务描述)
- status: str ∈ {"not_started", "in_progress", "completed", "failed", "cancelled"}
- created_at: datetime
- updated_at: datetime
- priority: int ∈ [1, 5]  (5 = 最高)
- related_event_ids: List[str]
- related_task_ids: List[str]
- confidence: float ∈ [0.0, 1.0]  (提取置信度)
- source_pointer: str  (指向原始归档/对话片段的指针)

## 事件节点 (EventNode)
- event_id: str (唯一ID)
- title: str
- description: str
- event_type: str ∈ {"decision", "outcome", "milestone", "error", "discovery", "change", "other"}
- timestamp: datetime
- entities: List[str]  (涉及实体)
- outcome: str  (结果摘要)
- related_task_ids: List[str]
- related_event_ids: List[str]
- confidence: float
- source_pointer: str

## 关系节点 (RelationNode)
- relation_id: str
- source_node_id: str
- target_node_id: str
- relation_type: str ∈ {"depends_on", "causes", "during", "part_of", "related_to", "blocks", "triggers", "other"}
- weight: float ∈ [0.0, 1.0]  (关联强度)
- description: str
- confidence: float
- source_pointer: str

## 价值评估字段（后续阶段补充）
- access_count: int  (访问次数)
- last_accessed: datetime
- importance_score: float ∈ [0.0, 1.0]  (重要性评分)
- decay_rate: float ∈ [0.0, 1.0]  (衰减速率)

## 原文归档模块 (observation_pack.py)
- 大输出/大文档/长对话 → 本地磁盘归档
- 返回 stable handle (文件路径或引用ID)
- 原文保留，上下文只留摘要+handle

## 图谱提取模块 (graph_extractor.py)
- 从归档内容自动提取 TaskNode/EventNode/RelationNode
- 小模型辅助提取（支持本地模型）
- 提取结果带 confidence 和 source_pointer

## 证据核验模块 (evidence_verifier.py)
- 核验提取的节点是否有原文支撑
- 核验通过 → 允许写入图谱
- 核验失败 → 标记为低可信，需人工或二次提取

## 图谱写入模块 (graph_writer.py)
- 向本地图谱存储（SQLite + JSON/或图数据库）写入节点
- 记录 timestamp, confidence, source_pointer
- 支持增删改查

## 图谱检索模块 (graph_retriever.py)
- 根据新提问检索相关节点（语义匹配 + 关键词 + 关系遍历）
- 返回 top-k 相关节点，带相关度分数
- 支持向量嵌入模式和全文检索 fallback

## SoL-Pi 上下文管理集成 (context_manager.py)
- 新提问 → 先用图谱检索筛选相关节点
- 图谱节点 → 放入上下文（受限数量）
- 再应用 SoL-Pi 效率优化：
  - Action Fusion：确定性流合并
  - Online Context Compact：经济学触发压缩
  - ObservationPack：大输出归档
  - Reducer：小模型预筛 + 证据核验

## 检索→压缩协同
- 图谱检索作为第一道筛选（滤掉大部分无关历史）
- SoL-Pi 上下文管理作为第二道精筛+效率优化

## 节点价值评估 (value_evaluator.py)
- 输入：节点的 access_count, last_accessed, 关联密度, 关键性信号
- 输出：importance_score ∈ [0.0, 1.0]
- 规则：
  - 高频访问 → 高分
  - 时间衰减 → 老节点分数下降（可配置衰减率）
  - 关联密度高（多关系/多任务关联） → 高分
  - 关键成果/错误/决策等特殊事件类型 → 加权

## 价值对压缩的影响
- 高价值节点 → 保护（不参与压缩或压缩更保守）
- 低价值节点 → 可压缩/摘要/遗忘候选

## 路由判断 (routing.py)
- 输入：对话长度、任务复杂度信号、是否涉及已有图谱节点
- 输出：路由决策 ∈ {"lightweight", "standard", "full_graph"}
- 规则：
  - 极短对话（<=3 条消息）→ lightweight：
    - 不启动图谱写入
    - 不启动复杂图谱检索
    - 先跑 Action Fusion、本地缓存等轻量机制
  - 中等对话 → standard：
    - 图谱检索（有限）
    - 可能写入图谱（取决于内容价值）
  - 长对话/任务积累型 → full_graph：
    - 完整图谱检索
    - 完整图谱写入 pipeline

## 经验积累接口 (evolution_interface.py)
- 每次优化决策的结果 → 写入图谱（经过核验）
- 下次会话检索图谱 → 指导决策：
  - 哪些任务流更省 token
  - 哪些压缩策略更合适
  - 哪些节点检索更准确

## 渐进迭代约束
- 图谱提供经验积累基础
- 检索越来越准 → 决策参考越来越好
- 压缩/Fusion配置越来越贴合实际使用
- 约束：禁止一步成飞轮的承诺，逐步迭代
